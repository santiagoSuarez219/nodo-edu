En el desarrollo de software real, no es suficiente escribir código que funcione. También es necesario **organizar el trabajo**, evitar errores en equipo y mantener versiones estables del sistema mientras se agregan nuevas funcionalidades.

En esta sesión avanzamos en la construcción del **sistema de información académico del colegio**, incorporando una práctica profesional fundamental: el **manejo de ramas en Git y GitHub**.

---

## ¿Por qué usar ramas en el desarrollo del sistema académico? 🌳

Recordemos que estamos construyendo un sistema que debe gestionar:

- estudiantes
- profesores
- asignaturas
- información personal
- información de contacto
- matrícula
- cursos asignados
- cupos máximos por asignatura

Si todos los cambios se hicieran directamente sobre la rama principal (`main`), cualquier error podría afectar todo el sistema.

Las ramas permiten:

✅ trabajar nuevas funcionalidades sin dañar el sistema estable

✅ dividir el trabajo entre integrantes del equipo

✅ probar cambios antes de integrarlos

✅ mantener un historial claro del desarrollo

✅ simular el flujo de trabajo profesional de proyectos reales

Por ejemplo, mientras un estudiante implementa la clase `Profesor`, otro puede trabajar en `Asignatura` sin interferencias.

---

## ¿Qué es una rama en Git? 🌱

Una **rama** es una línea de trabajo independiente dentro del repositorio.

Permite desarrollar funcionalidades sin afectar la versión principal del proyecto.

En nuestro sistema académico, podemos usar ramas como:

```
feature-estudiantes
feature-profesores
feature-asignaturas
feature-menu-principal
```

Cada una representa una funcionalidad específica del sistema.

La rama principal (`main`) siempre debe contener la versión estable del proyecto.

---

## Flujo de trabajo básico con ramas en Git 🔄

El flujo recomendado para este curso será:

Crear una rama nueva → desarrollar funcionalidad → guardar cambios → subir la rama → integrar en main

Este flujo permite construir el sistema académico de forma organizada y segura.

---

## Creación de una rama para desarrollar la clase Profesor 👨‍🏫

Durante la clase trabajamos sobre el repositorio del sistema académico creando una nueva rama para implementar la lógica de los docentes.

Primero verificamos la rama actual:

```bash
git branch
```

Luego creamos una nueva rama:

```bash
git checkout -b feature-profesores
```

A partir de este momento, todos los cambios quedan aislados de la rama principal.

---

## Implementación de la clase Profesor en la nueva rama

En esta rama desarrollamos la clase `Profesor`, agregando atributos propios del sistema del colegio:

- fecha de vinculación
- número de cursos actuales
- validación de máximo 5 cursos por periodo académico

Ejemplo conceptual:

```java
public class Profesor extends Persona {

    private String fechaVinculacion;
    private int numeroCursosActuales;

    public Profesor(String nombre, String id, String fechaNacimiento,
                    String direccion, String telefono, String correo,
                    String fechaVinculacion) {

        super(nombre, id, fechaNacimiento, direccion, telefono, correo);
        this.fechaVinculacion = fechaVinculacion;
        this.numeroCursosActuales = 0;
    }

    public void agregarCurso() {
        if (numeroCursosActuales < 5) {
            numeroCursosActuales++;
        } else {
            System.out.println("El docente ya tiene el máximo de cursos permitidos.");
        }
    }
}
```

Aquí aplicamos una regla del sistema real: ningún docente puede superar cinco cursos.

---

## Guardar cambios en la rama creada 💾

Después de implementar la funcionalidad, registramos los cambios:

```bash
git add .
git commit -m "Add clase Profesor con validacion de maximo 5 cursos"
```

Un buen commit describe claramente lo que se hizo.

Ejemplo correcto:

```
Add clase Profesor con validacion de maximo 5 cursos
```

Ejemplo incorrecto:

```
Cambios
```

---

## Subir la rama a GitHub ☁️

Ahora publicamos la rama en el repositorio remoto:

```bash
git push -u origin feature-profesores
```

Esto permite compartir el avance con el equipo.

---

## Integración de la rama con la versión principal del sistema 🔗

Regresamos a la rama principal:

```bash
git checkout main
```

Luego integramos la nueva funcionalidad:

```bash
git merge feature-profesores
```

Ahora la clase `Profesor` forma parte oficialmente del sistema académico.

Finalmente eliminamos la rama local:

```bash
git branch -d feature-profesores
```

---

## Buenas prácticas al trabajar con ramas en proyectos Java 🧠

Trabajar con ramas no es solo usar comandos. También implica organización.

Algunas recomendaciones importantes:

Usar nombres claros en las ramas:

```
feature-estudiantes
feature-asignaturas
feature-menu
```

Evitar nombres como:

```
rama1
cambios
prueba
```

Cada rama debe contener una sola funcionalidad.

No mezclar:

❌ cambios en estudiantes + profesores + menú en una misma rama

Preferir:

✅ una rama por funcionalidad

Siempre probar el código antes de hacer merge.

Nunca trabajar directamente sobre `main`.
